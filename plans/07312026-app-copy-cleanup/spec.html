Why

The app has grown through many feature passes, and visible copy now mixes product labels, workflow guidance, implementation rationale, prototype disclaimers, later-phase notes, and repeated explanatory text. That makes operational pages harder to scan.

The goal is not to make the interface vague. It is to remove redundant or unnecessary text while keeping the words that help users complete work: labels, status text, validation, destructive-action warnings, access notices, empty states, and short form guidance.

What

Perform a copy-only cleanup across the React app. Edit existing visible text in place, keeping behavior, routing, permissions, data calculations, component structure, class names, styling, and visual design unchanged. Removing an entire redundant text paragraph is allowed when the paragraph itself is the copy problem; do not add layout/style changes to compensate. An import or prop may be removed only when deleting approved visible copy makes it unused.

Execution priority: first remove redundant route-header intro paragraphs, then remove prototype/later-phase and implementation-facing visible copy, then review smaller muted helper copy case by case.

User decisions recorded on 2026-07-31: redundant intro paragraphs should be removed entirely, not shortened; prototype/later-phase visible copy should be removed; dialogs and sheets are in scope.

Assumption: this pass targets English product copy only. Domain constants and client-stated labels remain unchanged unless a label is visibly redundant in context.

Constraints

Must

  • Read and preserve CONVENTIONS.md and DEVIATIONS.md constraints during execution.
  • Start with the six route-header intro paragraphs named in Context. Remove each entirely when the header, tabs, counts, filters, or actions already communicate the same information.
  • Remove visible prototype/later-phase/implementation-facing copy, including inside dialogs and sheets, unless the user would otherwise misunderstand a disabled or non-delivery workflow.
  • Review smaller muted helper copy case by case. A muted style class is not by itself proof that the text is redundant.
  • Preserve navigation labels, form labels, placeholders that prevent mistakes, error text, status labels, accessibility names, and destructive-action confirmations.
  • Keep every displayed ASSUMPTIONS value paired with <AssumedChip />.
  • Keep money/date wording consistent with formatPeso, date helpers, and domain label maps.
  • Keep copy professional, concise, and operational. Avoid marketing filler and implementation rationales in product screens.

Must Not

  • No route changes, permission changes, data model changes, store changes, or new dependencies.
  • No redesign, component replacement, color/theme changes, layout refactors, or icon-library changes.
  • Do not bulk-delete text based on classes such as text-muted, text-[11.5px], or leading-relaxed.
  • Do not modify className values, spacing utilities, grid/flex structure, or UI primitives for this cleanup. Remove an import or prop only when approved visible-copy deletion makes it unused.
  • No removal of audit, finance, approval, role-scope, or safety warnings if the user needs them to make a decision.
  • No native form controls; existing shadcn primitives stay in place.

Out Of Scope

  • New copywriting system, localization/i18n, CMS extraction, or content constants refactor.
  • Accessibility audit beyond preserving existing labels and names touched by the copy pass.
  • Visual redesign, density changes, feature behavior changes, new empty/loading states, or new routes.
  • Database migrations, backend work, and deployment configuration.

Risk

Level: 2 - Concern (broad UI copy blast radius, low technical complexity).

Risks Identified

  • Class-based deletion would remove real metadata and safety copy. Mitigation: route-header paragraphs are targeted first; small muted helper copy is reviewed by meaning, not class name.
  • Deleting necessary workflow guidance while removing filler. Mitigation: protect form guidance, destructive warnings, validation errors, role/access explanations, financial/audit decision context, and assumption disclosures.
  • Changing canonical domain wording accidentally. Mitigation: treat domain label maps as protected and prefer page-level copy edits.
  • Breaking accessibility names by shortening aria-label or screen-reader-only titles. Mitigation: only edit accessibility names when they become clearer and still identify the control or dialog target.
  • Large diff review fatigue. Mitigation: execute by feature group and keep copy changes small, with no unrelated formatting churn.
  • Role-specific pages may hide copy from a single demo role. Mitigation: acceptance must include owner/admin/manager/agent spot checks, not just one session.

Blast radius: every route listed above, shared shell chrome, shared empty/table/card primitives, dashboard cards, approval cards, sales dialogs/sheets, lot drawer sections, pricing dialogs/tabs, agent commission screens, burial scheduling sheets, map editor panels, toast descriptions, placeholders, and domain label consumers.

Pushback

  • A copy cleanup across all pages is not a quickfix. Recommended path is this spec-first branch, then a controlled -x implementation grouped by feature area.
  • Do not remove every muted sentence. Some text is an operational control, especially around payments, approvals, audit history, cancellation, unpublished map edits, and assumed business rules.
