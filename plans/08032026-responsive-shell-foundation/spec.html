Why

Route-specific responsive work needs two stable capabilities that the current shell does not provide: a safe place for one compact route action and a single safe-area geometry contract.

Putting Map or Dashboard imports directly into AppShell would make the shared shell depend on feature internals. Storing a temporary route action in persisted state would also let stale UI leak between routes and sessions.

This foundation adds only the generic ownership boundary. Individual route refinements remain responsible for their content, surfaces, and workflows.

What

Add a typed, route-scoped top-bar action contract with one rendered action, optional attention count, token-safe cleanup, and focus recovery. Add four shared safe-area variables and make the authenticated shell consume them exactly once.

Keep the existing desktop rail, compact navigation sheet, route title, location switcher, notification bell, display settings, theme toggle, account controls, skip link, route focus, and route announcement behavior.

Planning record: the -s phase created no application code, tests, runtime, acceptance artifacts, dependency change, commit, push, or merge. The current -x execution is limited to the task-owned files below.

Exact route-action API contract

Create src/components/shell/RouteTopBarAction.tsx. It owns the provider, route registration lifecycle, slot renderer, descriptor types, and a focused reducer/state transition boundary.

Public descriptor

  • Export RouteTopBarActionDescriptor with required id, label, icon, and onActivate fields.
  • id is a stable semantic identifier for QA and diagnostics. Lifecycle safety uses an internal mount token, not the public identifier.
  • label is the full accessible button name. It must describe the action, such as “Open dashboard”.
  • icon uses the repository's existing IconSvgElement type and renders through Icon.
  • onActivate is called only by the native button. Registration never invokes it.
  • Optional disabled uses native button semantics.
  • Optional badge contains a numeric count and required accessible label. Counts at or below zero do not render; visible counts above 99 render as 99+.

Public registration surface

  • Export useRouteTopBarAction(action), accepting RouteTopBarActionDescriptor | null and returning nothing.
  • Callers invoke the hook unconditionally and pass null when the action is inactive.
  • Export RouteTopBarActionProvider and RouteTopBarActionSlot for AppShell composition and the QA-only contract harness.
  • Calling the hook outside its provider fails immediately with a clear developer error.

Lifecycle invariants

  • Each mounted hook owns one stable internal token and the current React Router location.key.
  • The registry stores at most one active registration. A newer registration replaces the previous registration and never allows two buttons.
  • An update or cleanup applies only when its token still owns the active registration. Stale cleanup cannot clear a newer action.
  • Removing the newest action clears the slot; the previously replaced action never resurfaces.
  • The slot renders an action only when its recorded route key equals the current route key. A navigation therefore hides stale content before effect cleanup completes.
  • Registration state is local React context state. It never enters Zustand, localStorage, URL state, route config, or a feature store.
  • Separate stable registration controls from changing slot state so route callers do not subscribe to their own descriptor updates or enter an effect-driven render loop.
  • Descriptor updates refresh labels, badges, disabled state, icons, and activation behavior without remounting the focused button solely because the count changed.
  • Strict Mode mount, cleanup, and remount behavior leaves exactly one correct action or an empty slot.

Downstream ownership

  • Dashboard refinement owns the attention count, badge wording, semantic icon, and controlled Dashboard activation behavior.
  • Map refinement obtains that Dashboard-owned descriptor and calls useRouteTopBarAction() only while its constrained Map layout needs the launcher.
  • The shell renders the descriptor consistently but never imports Map, Dashboard, Sales, or route feature modules.
  • Other route refinements may use the same single-action contract later. They must not extend it into a generic toolbar without a new spec.

Responsive shell and geometry contract

Safe-area source of truth

  • Define exactly four safe-area root variables in src/styles/globals.css: --shell-safe-top, --shell-safe-right, --shell-safe-bottom, and --shell-safe-left.
  • Each variable resolves from its matching env(safe-area-inset-*) value with a zero fallback.
  • The authenticated shell frame applies all four variables once within its existing 100dvh border box.
  • The portaled mobile navigation receives its own safe top, bottom, and left boundaries because it is outside the frame. Its close control and footer remain inside those boundaries.
  • The skip link offsets from safe top and left instead of fixed viewport edges.
  • Do not modify global shadcn sheet, dialog, popover, or toast primitives. This plan only adapts the shell's mobile navigation instance.

Route geometry ownership

  • #main-content is the actual safe-area-adjusted route viewport below the measured TopBar. Route roots use its content box and must not subtract fixed rail or TopBar dimensions.
  • Add stable shell data attributes for QA and measurement: the authenticated frame, TopBar, main content, mobile navigation, and route-action button.
  • Routes rendered inside #main-content do not add the shell safe variables again. That would double inset ordinary route content.
  • A route-owned fixed or portaled surface outside #main-content may consume the four variables. That surface owns proving it does not double inset.
  • Keep h-dvh, min-h-0, and the current persistent shell mount. Do not add a visualViewport listener or a second viewport-height state system.
  • When the visual viewport height changes for a soft keyboard or orientation, TopBar remains visible and main content receives the remaining height without resetting route state.

Shell navigation layer ownership

  • When compact navigation is open, its backdrop and sheet are the topmost application-owned modal surface. Route-owned chrome, panels, drawers, maps, tooltips, and notices must paint and receive pointer input below them.
  • Define --shell-layer-mobile-navigation-backdrop: 1000 and --shell-layer-mobile-navigation: 1010 on :root. The content layer is above the backdrop; both are above the reserved route-owned ceiling of 999 and the current Map controls at 600, Dashboard slot at 630, and Map presentation and lot-detail surfaces at 650.
  • Apply the content layer only through the existing .shell-mobile-navigation marker. Apply the backdrop layer through body:has(> .shell-mobile-navigation[data-state='open']) > [data-slot='sheet-overlay'][data-state='open'], matching the inspected Radix portal shape where both nodes are direct body children.
  • Do not edit src/components/ui/sheet.tsx, raise every global Sheet, lower Map/Dashboard layers, close or collapse Dashboard state, or introduce route-specific imports into the shell.
  • Opening navigation does not unmount or mutate Map, Dashboard panel state, selected lot, filters, zoom, center, or presentation. Closing with Escape, backdrop, close button, or a navigation choice preserves the owning route state.
  • Radix remains responsible for modal focus containment, scroll lock, Escape, backdrop dismissal, and return focus. A navigation choice that changes route preserves RouteAccessibility as the final focus owner for #main-content.

Top-bar hierarchy

  • At constrained widths the order is mobile navigation, flexible route title, optional route action, then notifications.
  • Navigation, route action, and notifications retain 44px targets. The title is the only item allowed to yield horizontal space.
  • Below sm, the title may wrap to at most two lines so current route names remain visibly useful. From sm upward it stays on one line. The full text remains in the h1, document title, route announcement, and mobile navigation even if future longer text is visually clipped.
  • The slot returns no wrapper when empty, so routes without actions preserve current spacing.
  • The route action is one compact icon button wrapped in the existing Tooltip with its action label. Its accessible name and optional badge text do not depend on tooltip, color, or animation.
  • Badge updates are not a live region. The current count is available in the button's accessible name when the user reaches it.
  • Preserve the existing breakpoint visibility for “Viewing as”, location, display settings, theme, and account controls.
  • Reduced-motion preferences continue through the existing global CSS and MotionConfig; the new action adds no essential animation.

Accessibility contract

  • Render the route action as the existing native Button and semantic Icon, not a clickable wrapper or ARIA-recreated button.
  • Expose the full action label through aria-label. When a positive badge exists, include its required accessible label in the button name.
  • Keep the icon decorative because the button owns the accessible name. The visible badge supplements but never carries meaning alone.
  • Registration, count changes, and ordinary layout changes do not move focus.
  • If the focused route action unregisters without navigation, restore focus to #main-content after the slot clears.
  • If navigation removes the action, preserve RouteAccessibility as the single route-focus owner. Do not produce a competing focus race.
  • The action owner controls focus when activation opens a dialog, sheet, or other surface. The shell does not guess that surface's focus target.
  • Mobile navigation keeps its existing Radix focus containment, Escape, close control, labels, and focus return.
  • Verify keyboard order, visible focus, 44px targets, 200% zoom, extra-large text, reduced motion, and actual assistive names manually as well as through browser assertions.

Risk, pushback, and mitigations

RiskLevel and impactRequired mitigation
Stale route registration Level 3. An action from the previous route can trigger the wrong feature. Route-key visibility, stable mount tokens, guarded update/cleanup, no previous-action resurrection, and direct harness coverage.
Context render/effect loop Level 3. Descriptor updates could re-render callers and register forever. Separate stable registration controls from changing slot state; callers do not subscribe to the action they publish; test inline descriptor updates.
Feature coupling in shell Level 3. Shared infrastructure starts importing Dashboard or Map internals. Descriptor-only public API, static import search, read-only route files, and stop execution on any feature import request.
Safe-area double padding Level 3. Routes become cramped or misaligned on notched devices. Apply variables once to the frame, separately to the portaled mobile sheet, and document #main-content as already inset.
Focused action disappears Level 2. Keyboard focus falls to the document body. Restore same-route unregister focus to #main-content; preserve Route Accessibility as navigation focus owner.
Top-bar collision Level 2. Long titles or large text hide primary controls. Keep three 44px controls non-shrinking, let title yield, preserve full semantic title, and test the longest labels at 320px and 200% zoom.
Desktop rail regression Level 2. Shared frame changes alter persisted desktop navigation. Do not change the storage contract or rail state; compare open/collapsed behavior before and after constrained visits.
No production action consumer yet Level 2. The public API could ship unproved or dead. Use a QA-only Vite fixture that consumes the real exports; record Map and Dashboard as downstream owners; do not add a fake production route.
Browser timing flake Level 2. Route effects and responsive checks pass only with sleeps. Wait on route paths, action data attributes, focus targets, and layout frames; use no arbitrary long delay as a pass signal.
Route surface paints over shell navigation Level 3. The hamburger appears to fail because Map or Dashboard remains visible and clickable above an open, focus-trapping navigation sheet. Reserve shell-owned backdrop/content layers above the route ceiling; target only the open mobile-navigation portal; assert paint hit-testing, pointer blocking, focus containment, dismissal, and preserved Dashboard/Map state.

Rejected alternatives: persisted Zustand state would outlive the route; route metadata would force route registration edits; feature imports would invert ownership; a production QA route would expand user-facing scope; lowering Map/Dashboard layers or collapsing the Dashboard would couple shell navigation to one route and mutate user state; changing the global Sheet primitive would broaden the blast radius to unrelated feature sheets.

Verification and acceptance strategy

Layer 1 — static and automated

  • npx tsc --noEmit -p tsconfig.app.json.
  • npm run lint.
  • npm run build.
  • npm run validate:mock.
  • npm run qa:shell with configurable BASE_URL and BROWSER_PATH.
  • npm run qa:accessibility against the same runtime.
  • npm run qa:smoke to protect authenticated routes and role guards.
  • Static import search: shell files contain no imports from features/map, features/dashboard, or features/sales.
  • Static storage search: route-action implementation contains no Zustand, localStorage, session storage, or URL persistence.

Action-contract cases

  • No registration renders no slot wrapper and consumes no width.
  • A named registration renders exactly one 44px native button with its semantic icon.
  • A positive count renders one capped visual badge and appends required badge wording to the button name.
  • Zero and negative counts render no badge.
  • Updating the count, label, disabled state, or callback updates the active action without count-driven focus loss.
  • Registration B replaces A; cleanup from A cannot clear B; cleanup from B clears the slot; A never resurfaces.
  • A route-key change hides the prior action before its cleanup runs.
  • Strict Mode effect replay leaves one action and no leaked registration.
  • Focused same-route removal returns focus to main; route navigation uses existing route focus and announcement.
  • Using the hook outside the provider produces the expected developer error in an isolated harness case captured by its test error boundary; it must not become an uncaught page error.

Responsive browser matrix

  • 320x568: no document horizontal overflow; navigation, title, optional action, and notification remain reachable.
  • 360x800, 390x844, and 430x932 portrait: optimized compact hierarchy, sheet navigation, focus return, and action badge.
  • 640x960 and 768x1024 portrait; 960x640 and 1024x768 landscape: stable orientation and route state with no top-bar collision.
  • 1280x800, 1440x900, 1680x1050, and 2000x1000: desktop rail open/collapsed persistence and all existing top-bar controls.
  • Run standard and extra-large text. Verify the longest route labels, including “Sales & Payments” and “Pricing & Tiers”.
  • Override the four CSS variables with deterministic non-zero test values and assert frame, skip-link, and mobile-sheet boundaries consume them once.
  • Shrink viewport height while the mobile sheet is open to model visual-viewport change; assert header, navigation, and footer remain reachable.
  • Navigate across every registered authenticated route and assert no previous route action, focus leak, error boundary, forbidden screen for the seeded role, or horizontal overflow.

Mobile-navigation collision cases

  • At 320x568 and 390x844, open compact navigation on /map with Dashboard hidden, docked, and full. The sheet and backdrop paint above the Dashboard slot and all Map chrome.
  • Repeat with Map and list presentation. Use the QA fixture with a synthetic route-owned blocker at the reserved ceiling of 999 to prove the generic contract; statically assert the current lot-detail layer at 650 remains below that ceiling without requiring unavailable lot seed data.
  • Assert computed layers are backdrop 1000 and content 1010. At a point inside the sheet, document.elementFromPoint() resolves within [data-shell-mobile-navigation]; at a point outside, it resolves to the active sheet overlay, never Map, Dashboard, or lot detail.
  • While open, Tab and Shift+Tab remain within the sheet; underlying Map/Dashboard controls cannot be clicked; body scroll lock remains active.
  • Escape, backdrop click, and close button dismiss and return focus to the hamburger without mutating route state. Choosing a navigation item closes the sheet, changes route once, removes scroll lock, and leaves final focus on #main-content through RouteAccessibility.
  • After close, verify Dashboard state, Map presentation, filters, selection, center, zoom, and route state match their pre-open values whenever that state is available in the current deterministic fixture.

Manual verification

  • Actual 200% browser zoom at 320-effective width and representative desktop width.
  • Keyboard-only navigation through skip link, mobile navigation, route action, notifications, and route changes.
  • Screen-reader or accessibility-tree inspection of the full route title and action name with and without a badge.
  • Notched device or simulator in portrait and landscape using real environment safe-area values.
  • Actual soft keyboard with the mobile sheet and a route-owned focused field; no hidden shell navigation or document overflow.
  • Reduced-motion system and in-app preference; no essential state depends on motion.

Fixtures: use deterministic local user IDs and isolated local storage. The action harness uses synthetic labels and counts. It imports production shell modules but no feature data.

Flake controls: wait on data attributes, path changes, focus, and computed rectangles. Do not treat map tiles, animation duration, or arbitrary sleep completion as a pass signal.
