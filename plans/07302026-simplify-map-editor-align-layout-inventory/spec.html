Why

The current /map-editor exposes technical tools first: Select, Edit Block, Block, Grid, Draw Lot, and Overlay. Non-technical admins need a default workflow that answers one plain question: what layout geometry should be aligned against the base map or uploaded site plan?

This feature separates geometry correction from inventory mutation. Alignment can move displayed shapes, including sold or occupied lot polygons, while preserving every business record attached to those lots.

What

Redesign /map-editor into two modes: Align Layout as the default simple workflow, and Advanced Inventory for creation, regeneration, status, tier, renumbering, and deletion operations.

Done means an admin can align the entire cemetery layout, one block, selected lots, or a site-plan overlay with direct drag, resize/scale, rotate, nudge, cancel, save draft, undo, discard, and publish behavior. Alignment must preserve lot identity and all business data.

Baseline Source Of Truth

The source-of-truth contract for execution is:

  • Alignment changes geometry only. It may update Block.polygon, Block.centroid, Lot.polygon, Lot.centroid, Lot.areaSqm, and MapOverlay.bounds/rotationDeg/opacity when editing an overlay.
  • Alignment must not change business data. It must not change lot IDs, block IDs unless explicitly using Advanced Inventory move-to-block, lot numbers, tier IDs, statuses, holds, owners, contracts, payments, interments, capacity, not-for-sale reasons, or notes.
  • Protected lot policy is mode-specific. Align Layout may move sold or occupied lot geometry because that is visual correction. Advanced Inventory still must not silently move, delete, recode, or resize sold or occupied lots as inventory operations.
  • Base maps and uploaded site plans are references. Neither satellite imagery nor uploaded site-plan images are treated as legal truth. They help the admin visually align geometry.
  • Draft publish model remains. All changes remain staged until Publish. Discard reverts to live data. Undo/redo must cover saved alignment changes.

Product Model

Align Layout

  • Default mode when opening /map-editor.
  • Targets: Entire cemetery, Block, Lots, Site plan.
  • Controls: drag to move, handles to scale/resize, round handle to rotate, arrow keys to nudge, Shift for constrained scale.
  • Copy: "Records locked. This only moves shapes on the map."
  • Actions: Cancel, Save draft, Undo, Redo, Discard, Publish.

Advanced Inventory

  • Secondary mode for technical inventory edits.
  • Contains current Block, Grid, Draw Lot, selection/bulk actions, renumber, tier/status, delete, move-to-block, repair overlaps.
  • Keeps protected-lot safeguards for sold/occupied inventory operations.
  • Uses current dialogs and warnings, but is not the default path for admins aligning maps.

Constraints

Must

  • Default to Align Layout, not the existing technical tool strip.
  • Support alignment targets: entire cemetery, one block, selected lots, and active site-plan overlay.
  • Use one shared geometry transform path for move, rotate, and scale where practical.
  • Preserve draft, publish, discard, undo, redo, and route blocker behavior.
  • Preserve lot business data during alignment, including sold and occupied lot records.
  • Retain Advanced Inventory for creating, generating, drawing, renumbering, status/tier changes, deletion, and move-to-block inventory operations.
  • Show visible alignment readouts and clear target labels.
  • Use project UI primitives and icon conventions.
  • Add automated verification for geometry-only alignment and protected-lot data preservation.

Must Not

  • Do not edit frozen @/domain constants or action enum.
  • Do not introduce new dependencies or drag libraries.
  • Do not implement real map-canvas rotation.
  • Do not treat satellite imagery or uploaded plans as authoritative survey data.
  • Do not silently change lot IDs, lot numbers, block assignments, statuses, tiers, contracts, payments, owners, interments, capacity, notes, or prices during alignment.
  • Do not remove Advanced Inventory capabilities.
  • Do not hide publish/discard warnings.
  • Do not add native form controls in app UI.

Out Of Scope

  • Database schema changes or real persistence backend work.
  • Legal survey/georeferencing calibration beyond manual visual alignment.
  • Mobile-first redesign. The editor remains desktop/tablet oriented, but must not break narrow viewports.
  • Changing the public/live map behavior outside published geometry and existing overlay visibility.
  • Reworking pricing, contracts, burials, or sales flows.

Risk

Level: 4 - Major Impact. This changes how admins manipulate cemetery geometry, including sold/occupied lots in alignment mode.

Risks Identified

  • Geometry correction can be mistaken for inventory mutation. Mitigation: split modes, use "Records locked" copy, and make alignment actions update only geometry fields.
  • Protected lots can visually move. Mitigation: allow this only in Align Layout, add audit labels that explicitly say geometry was aligned, and keep Advanced Inventory protections unchanged.
  • Pointer complexity can make EditorSurface.tsx unmaintainable. Mitigation: extract transform/session helpers and keep surface responsible for event wiring only.
  • Whole-layout transforms can corrupt relative geometry if block and lot transforms diverge. Mitigation: one shared transform function must apply to blocks and lots from the same baseline snapshot.
  • Audit labels currently misdescribe geometry edits as block creation/resizing. Mitigation: update publish diff labels and lib/audit.ts description behavior to prefer recorded map-editor summaries for block.created events without editing @/domain.
  • Admin may align to inaccurate satellite imagery. Mitigation: UI copy says base map and site plan are references only.

Blast radius: /map-editor, live map geometry after publish, draft publish audit, map editor undo/redo, overlay placement, lot canvas render records, protected-lot semantics, QA smoke/walkthrough scripts.

Pushback

  • "Everything drag/drop/resize" is not an execution contract. The correct contract is geometry-only alignment with inventory mutation separated. Future-us will hate a single mode that makes visual correction and business mutation look identical.
  • The previous "never move sold lots" rule was right for inventory edits but wrong for alignment corrections. This spec narrows that rule instead of deleting it.
  • Adding more tooltips to the existing toolbar is not enough. The default workflow itself must change.
