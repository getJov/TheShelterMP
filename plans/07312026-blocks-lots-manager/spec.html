Why

The step-by-step wizard fights the actual job: tracing a messy, surveyed reality. The user wants a flat two-level manager — blocks, then lots — with free-form drawing, bulk generation to avoid one-by-one work, and precise per-lot adjustment. Confirmed by user Q&A on 2026-07-31.

What — the locked design

  • Sidebar home: list of blocks (+ Add block) only, plus compact Site plan and Base map sections. No steps, no modes.
  • Add block: Rect or Free-form draw → card offers Free form (empty) or Autofill R × C. Autofill divides the block into exactly R × C cells (cells ≈ 86% of pitch, centred; tier sets price/colour, not the footprint). All generated lots stay individually editable (move / retier / delete).
  • Block view (click a block): d-pad move (step cycle 0.05/0.25/1 m), rotate ±0.5°/±5°, scale steppers + on-map handles, rename/code/tier, delete block (with its lots), and the lot tools below.
  • Lot tools: Rect + free-form lot drawing; selection (click, band); generators — 10 / 100 / fill copies of the selected lot or group tiled as a unit toward left/right/top/bottom, clipped to the block (place what fits, report the rest); selection d-pad + width/length steppers; tier (with price), status, renumber, delete.
  • Drag-move on map for blocks (block + its lots move together) and for selected lots; d-pad remains the precision path.
  • Shrink guard: a block can never scale below its content. Outcast lots relocate to free interior space when possible; otherwise unprotected outcasts are deleted (single undo, counted in a toast). Protected lots (sold/occupied/contract/interments) are never moved or deleted — they define the hard minimum.
  • Block delete refuses while the block contains protected lots.
  • Validation is advisory: overlaps/out-of-block show as a warning badge and a list in the publish dialog; publishing is never blocked by them.
  • Draft survives reload: dirty drafts auto-save to localStorage and restore on load (same location, same dataset version rules as today; publish/discard clears).
  • getpropsie(): global devtools function returning + logging + copying the draft's {blocks, lots, overlays} JSON. The seed accepts a literal layout module (src/mock/park-layout.ts, default null) that, when set from a paste, becomes the demo default.

Context & strategy

Reuse over rewrite (the store already knows how)

  • Move/rotate = existing applyAlignmentTransform (target 'lots' / 'block'); drag sessions copy the proven alignmentSession pattern (base snapshot → live preview → one undo commit).
  • Generators build on duplicateLots mechanics + buildLots; autofill divides the block's local extent (via toLocal/fromLocal).
  • Block scale handles = existing editingBlock machinery, its commit routed through the new outcast guard.
  • Store keeps vestigial mode fields pinned (editorMode: 'inventory', layerMode: 'lots') so untouched internals keep working; dead-code sweep is a follow-up, not this change.

Removed UI (full replace, per user)

GuidedWorkflowPanel, step cards, Align-mode panel, GridPanel flow, BulkActionsBar (its tools consolidate into the block view). OverlayPanel is reused on the home screen.

Reference analogs: sidebar structure follows the existing Sidebar.tsx conventions (PanelSection/bits.tsx); new store actions follow duplicateLots/commitBlockEdit shapes.

Risk

Level 3 (approved): replaces the editor shell. Mitigations: store contract stays additive; geometry math reuses proven helpers; acceptance list drives a full browser pass; the old flow is deleted only at the UI layer this round.

  • Outcast relocation is a heuristic (nearest free interior slot, greedy). Mitigation: if no slot in a bounded search, fall to remove-with-count; document; everything is one undo.
  • Context/turn budget: build is sequenced store → surface → sidebar → seed so any interruption leaves a compiling app. Spec is the continuation contract.

Blast radius: map-editor feature folder, helpers.ts validation, PublishDialog, seed (seed-park.ts), MapEditorPage. Park Map untouched.
