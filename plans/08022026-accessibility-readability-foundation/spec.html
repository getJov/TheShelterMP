Why

The primary users include older adults who may have reduced visual acuity, contrast sensitivity, dexterity, concentration, or short-term memory. The current interface uses dense typography that makes routine work harder than necessary.

The source contains 982 fixed pixel text-size utilities. Of those, 718 are 12.5px or smaller and 865 are below 14px. The app also contains 74 truncation rules, 130 fixed pixel widths, and 37 hidden-overflow rules.

A font-size switch alone would not solve the problem. The approved work repairs the default, adds restrained preferences, improves shared operability, and deeply remediates the three most important workflows.

What

Build a WCAG 2.2 A/AA-oriented accessibility and readability foundation without claiming formal certification. Preserve the existing brand, domain behavior, routes, role policy, finance calculations, and core workflow intent.

The whole application receives readable default typography, semantic type tokens, comfortable shared controls, enhanced contrast, persistent display preferences, responsive shell behavior, and reliable keyboard focus. Deep accessibility work applies to Map and Lot Detail, Sales and Payments, and Burials.

The map gains an accessible List presentation. It must use the same scoped lot data, filters, selection, and detail drawer as the canvas map.

Approved Product Decisions

  • Repair readability by default for every user.
  • Provide Standard, Large at 112.5%, and Extra Large at 125%.
  • Include Enhanced Contrast in the first delivery.
  • Keep comfortable control sizing as the default. Do not add a density preference.
  • Let users choose Follow Device or Reduced motion.
  • Persist accessibility preferences through logout and ?demo=1.
  • Keep localization out of scope. Keep English copy plain, direct, and consistent.
  • Support desktop, small laptop, iPad, and Android tablet in portrait and landscape.

  • Provide a permission-safe List alternative to the map canvas.

Baseline Source Of Truth

These values govern implementation. Feature files consume semantic type roles and must not invent replacement pixel sizes.

RoleStandardLargeExtra LargeUse
Micro13px14.625px16.25pxNon-essential badges, short codes, and compact metadata only
Caption14px15.75px17.5pxSupporting labels, table headers, hints, and timestamps
Body16px18px20pxParagraphs, table cells, dialog content, and primary information
Control16px18px20pxButtons, inputs, selects, tabs, menu items, and search
Small title18px20.25px22.5pxCards, drawers, and compact sections
Section title22px24.75px27.5pxPage sections and dialogs
Page title30px33.75px37.5pxMain page headings
Display38px42.75px47.5pxLogin and rare hero presentation
  • Body and control line height is at least 1.45. Micro and caption line height is at least 1.35.
  • Micro text never carries an error, required instruction, amount due, destructive consequence, or sole control name.
  • Standard ordinary text reaches at least 4.5:1 contrast. Meaningful control and focus boundaries reach at least 3:1.
  • Enhanced Contrast ordinary text targets at least 7:1. Meaningful control and focus boundaries target at least 4.5:1.
  • Primary controls target 44px. Small controls target 40px. Dense exceptions never fall below 24px and require compliant spacing.
  • Typography scales through named tokens. Do not change the root font size, use CSS zoom, transform the app, or override arbitrary class selectors.

Preference Schema

  • Use storage key shelter-accessibility with schema version 1.
  • Persist exactly four fields: textSize (standard | large | extra-large), contrast (standard | enhanced), motion (system | reduced), and mapPresentation (map | list).
  • Defaults are standard, standard, system, and map.
  • Parse fields independently. Preserve every valid field and fall back only invalid, missing, or unknown fields to its default.
  • Expose one typed read/apply boundary for pre-render initialization and one persisted Zustand store for in-app changes. Components must not access localStorage directly.

Accessibility Contract

Preferences

  • Provide Standard, Large, and Extra Large text; Standard and Enhanced contrast; Follow Device and Reduced motion; and Reset.
  • Expose display settings on login, in the authenticated top bar, and from the account menu when constrained.
  • Apply valid stored preferences before the first React render. Invalid or legacy values fall back safely.
  • Keep the preference storage key outside the ?demo=1 reset list and preserve it through sign-out.
  • Keep dark and light theme behavior intact. Enhanced Contrast overlays both themes.

Responsive And Input Behavior

  • Desktop reference: 1440x900. Small laptop: 1366x768. Tablet landscape: 1024x768. Tablet portrait: 768x1024.
  • At viewport or zoom-equivalent widths below 1024 CSS pixels, replace the permanent rail with an accessible sheet menu and simplify top-bar content.
  • Core content remains usable at 200% browser zoom. Non-exempt content reflows at an effective 320 CSS pixel width.
  • Map canvases and genuinely relational tables may retain two-dimensional interaction. Their surrounding controls and equivalent content must reflow.
  • No primary action depends on hover, drag, color, or pointer precision alone.
  • No document-level horizontal scrolling is allowed. Only the map canvas and genuinely relational table regions may scroll in two dimensions.

Map And List

  • Provide a named Map/List control on /map. Persist the chosen presentation with accessibility preferences.
  • List results use useMapData(), lotMatches(), and the same active filters.
  • List rows show lot code, block, status text, tier, authorized payment health, and authorized owner information.
  • Each row has an explicit View lot action that sets the existing selection and opens the existing detail drawer.
  • Paginate at 25 results per page. Announce result-count changes without moving focus.
  • Never place 904 canvas lots in the tab order. The List presentation is the non-canvas equivalent.

Keyboard, Focus, Forms, And Assistive Technology

  • Add a visible-on-focus skip link, stable main-content target, route focus behavior, and polite route announcement.
  • Use native buttons or links for actions. Do not add click handlers to non-interactive table headers or rows.
  • Maintain visible focus, predictable focus return, dialog containment, Escape behavior, and no hidden focused content.
  • Associate field errors and guidance with their controls. Mark invalid state and announce submit failures without color alone.
  • Prefer native semantics and existing Radix behavior before adding ARIA.

Risk And Blast Radius

Level: 4 - Major Impact. This is a cross-cutting presentation and interaction change across more than ten files and every registered route.

Risks

  • Shared primitive regression: 78 files consume Button, 23 consume Input, 24 consume SelectTrigger, and 21 consume DialogContent. Mitigation: change shared tokens first, then run route and viewport checks before feature work.
  • Permission leakage: a second lot presentation could bypass visibility rules. Mitigation: derive List data only from useMapData() and never read raw lots directly.
  • Content loss: larger text can collide with truncation, fixed widths, fixed panels, and hidden overflow. Mitigation: replace essential truncation with wrapping or disclosure and test every approved viewport and text size.
  • Focus regression: route, dialog, drawer, and sheet changes can steal or lose focus. Mitigation: document entry and return targets, then verify with keyboard and screen readers.
  • Brand flattening: stronger boundaries could make decorative surfaces heavy. Mitigation: separate interactive-boundary tokens from decorative line tokens.
  • Performance: rendering all lots in a DOM table would create unnecessary work. Mitigation: paginate List results at 25 and keep the canvas path unchanged.
  • False confidence: automated checks cannot prove assistive-technology usability. Mitigation: require manual NVDA, VoiceOver, and TalkBack acceptance evidence.
  • Parallel edit conflicts: multiple agents could touch shared tokens or shell files. Mitigation: T1-T3 stay sequential; T4-T7 have exclusive feature ownership.

Consumers

  • Global styles and controls: every route and every consumer of shared UI primitives.
  • DataTable: Sales, Burials, Lot Detail, Agents, Approvals, and Pricing.
  • Accessibility preferences: main.tsx, App.tsx, Login, AppShell, UserMenu, Display Settings, and Map/List presentation.
  • Map data and filters: MapCanvas, MapControls, MapLegend, Dashboard drill-downs, Lot List, and Lot Detail selection.
  • Core workflows: 17 Map files, 12 Lot Detail files, 20 Sales files, and 15 Burials files.
  • Secondary readability: Dashboard, Agents, Approvals, Pricing, Audit, and Map Editor feature trees.

Pushback

  • This must not execute as one unreviewed rewrite. Shared foundation, isolated feature tasks, and repeated integration checks are mandatory.
  • This spec is execution-ready only after a separate readiness review finds no blockers. It must never auto-execute from -s.
