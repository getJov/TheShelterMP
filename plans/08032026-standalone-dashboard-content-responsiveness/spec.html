Why

The standalone /dashboard route currently reuses the map panel's full layout. That reuse is useful for content, but it also makes the route depend on viewport breakpoints and panel-only actions. At narrow available widths, the header, period controls, cards, touch affordances, and large financial values do not have an explicit standalone contract.

The mobile outcome is quick triage, not a reduced dashboard. Eligible users see Needs Attention first, then the same authorized cards in the same source order at every width. Every detail remains reachable; responsive behavior must not silently hide cards, chart information, values, menus, or drill-down actions.

This work cannot honestly claim that the entire route is mobile-ready while AppShell is excluded. Its success boundary is the dashboard-owned content rendered inside the router outlet.

What

Make the standalone dashboard content adapt from a 320px available container through wide desktop. Introduce an explicit standalone-route surface context, a bounded 1400px content wrapper, container-aware card composition, a mobile-safe header and period selector, safe value wrapping, and accessible touch behavior.

Preserve the current data selectors, permission rules, finance formatting, date source, period and collapsed-card persistence, links, card variants, and all map dashboard-panel states. This is responsive refinement, not a visual redesign or a dashboard architecture rewrite.

In Scope

  • The header, reporting-period selector, action placement, cards, charts, legends, card menus, card rows, and card-local drill-down controls rendered by standalone /dashboard.
  • A typed standalone versus map-panel surface discriminator passed through shared dashboard components.
  • Route-only priority ordering and route-only responsive classes or container-query variants.
  • Focused automated browser coverage and post-execution acceptance artifacts.

Explicitly Out Of Scope

  • AppShell, the sidebar or navigation sheet, top bar, notification UI, account UI, shell breakpoints, and router-outlet geometry.
  • /map dashboard-panel dimensions, hidden/docked/full state transitions, map reserve width, bottom map strip, keyboard cycle, animation geometry, and map mounting behavior.
  • Other routes, route registration, permissions or role policy, data selectors, finance calculations, mock generation, APIs, database work, migrations, authentication, and new dependencies.
  • Global typography, theme, color, icon, motion, or broad visual redesign. Existing accessibility/readability changes are a protected baseline.

Responsive Product Contract

Surface Isolation

  • Add a typed surface discriminator with exactly two meanings: standalone and map-panel. Keep DashboardLayout responsible only for docked versus full card density.
  • DashboardPage passes surface="standalone". Every DashboardPanel state passes surface="map-panel". Shared components must not infer surface from window.innerWidth, pathname, or panel state.
  • Standalone-only responsive classes, ordering, menu visibility, and header behavior branch on the explicit surface. The map-panel branch preserves its current layout classes and behavior.
  • Do not change PanelState, DASHBOARD_PANEL_WIDTH, DASHBOARD_RAIL_WIDTH, DASHBOARD_MAP_STRIP_HEIGHT, useReserveMapWidth, map-store integration, or panel animation transitions.

Standalone Structure And Width

  • The route exposes data-dashboard-surface="standalone" on its dashboard-owned outer scroll surface and data-dashboard-content on the centered inner content wrapper.
  • The outer surface owns vertical scrolling. The inner wrapper is full width, centered, and capped at exactly 1400px, following the bounded-page direction used by Sales.
  • The inner wrapper is a named inline-size container. Standalone layout changes key off that container, not viewport breakpoints. Existing viewport classes may remain only in the protected map-panel branch.
  • Express the standalone contract with Tailwind v4 container utilities and dashboard-local class composition. Do not modify src/styles/globals.css, add a Tailwind plugin, or introduce a parallel breakpoint/token system. If the installed toolchain cannot express the contract locally, revise this spec before widening the file boundary.
  • Inline padding is 16px below a 640px available container and 24px at 640px and above. Card gaps are 12px below 640px and 16px at 640px and above.
  • No dashboard-owned descendant may increase the standalone surface's horizontal scrollWidth by more than 1px. Vertical page scrolling is expected.

Order And Role Behavior

  • For owner, admin, and manager when authorized, Needs Attention is the first card in DOM order and visual order at every available width. Render it as a full-width priority row before the hero and supporting grids.
  • Do not change the global order or size in cards.config.ts. Route-only composition extracts the authorized attention card, then renders the remaining authorized cards in their existing manifest order.
  • Do not use CSS order to create a different visual sequence. Keyboard, screen-reader, animation, DOM, and visual ordering must agree.
  • Agents do not receive Needs Attention or hidden financial cards. Their existing authorized order remains Inventory, Top Agents, Sales Activity, Commission Payout at every width.
  • No responsive breakpoint changes permissions, location scope, agent scoping, card count, card variant, data selector, or empty-state behavior.

Header And Period Controls

  • Below a 768px available container, the greeting/scope block and control block stack without overlap. The control block uses the full row.
  • Below 480px, the four period controls use visible labels Today, Week, Month, and Quarter in four equal-width slots; each retains its complete accessible name. At 480px and above, show Today, This week, This month, and This quarter.
  • The standalone Open the map action occupies a separate full-width row below 480px, remains at least 44px high, and becomes intrinsic-width when space permits. Period controls remain at least 40px high.
  • At 768px and above, the title and controls share the header row when they fit and may wrap cleanly. Greeting, frozen mock date, and location scope remain visible at every width.
  • The map-full Back to the map header keeps its current presentation unless an explicit regression fix is required for shared-component parity.

Cards, Values, Charts, And Touch

  • Standalone hero grid: one column below 640px, two columns from 640px through 959px, and no more than three columns at 960px and above.
  • Standalone supporting grid: one column below 640px, two from 640px through 895px, three from 896px through 1199px, four from 1200px through 1359px, and no more than five at 1360px and above.
  • Needs Attention, when present, spans the full standalone content width above both grids. Without it, no empty slot or placeholder is rendered.
  • Cards remain intrinsically tall. Do not use fixed card heights, content clipping, mobile-only detail removal, or automatic responsive collapse. Existing user-controlled collapsed state remains authoritative.
  • Formatted currency and numeric values keep the existing formatPeso options and semantic type roles. Values may wrap within their card and use safe overflow wrapping; they may not truncate, ellipsize, overlap controls, escape the card, or be reformatted solely to make layout pass.
  • Charts, legends, labels, deltas, subtitles, footers, rows, and drill-down routes remain present. Charts may resize, and text may wrap, but mobile must not substitute an information-poor summary.
  • On standalone, each options trigger is visibly discoverable without hover, has an accessible name, and is at least 40px square. The map panel may retain its current hover/focus reveal.
  • Primary route actions are at least 44px in one dimension. Secondary dashboard controls and actionable rows are at least 40px. A narrow visual chart segment is never the only touch path; its matching legend or named row provides the usable target.
  • The standalone card menu omits Open full screen because the route already is the full dashboard destination. Collapse/Expand and authorized detail actions remain. Map-panel menus retain Open full screen.
  • Do not convert non-interactive containers into custom buttons. Named native buttons and links remain the keyboard and touch paths; hover decoration is supplementary.
